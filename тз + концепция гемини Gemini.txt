Единое Техническое Задание и Концепция проекта «Gemini Flow»
1. Концепция проекта
Gemini Flow — это продвинутый Telegram-бот, который служит многофункциональным UI-клиентом для языковых моделей Google Gemini. Проект решает ключевую задачу пользователей: предоставляет удобный, структурированный и мобильный интерфейс для работы с API Gemini, превосходящий стандартные возможности.
Основная идея: Пользователь сам предоставляет свой собственный API-ключ Gemini ("Bring Your Own Key"). Бот, в свою очередь, обеспечивает всю инфраструктуру для комфортной работы: управление множеством независимых диалогов (чатов), умную обработку контекста для экономии токенов и гибкую систему подписок для доступа к расширенным функциям.
Ключевая аудитория: Разработчики, маркетологи, контент-мейкеры, студенты и энтузиасты, активно использующие нейросети для работы, творчества и личных задач.
Модель монетизации: Freemium-модель с двумя уровнями доступа.
Free-Tier (Бесплатный план):
API-ключ: Пользователь обязан предоставить свой ключ Gemini.
Чаты: Лимит на 1 активный чат.
Модели: Доступ только к базовым моделям (например, gemini-1.5-flash).
Premium-Tier (Платная подписка):
Чаты: Лимит увеличен до 10 чатов.
Модели: Доступ к продвинутым моделям (например, gemini-1.5-pro) с возможностью выбора модели для каждого чата.
Покупка: Подписка приобретается на различные сроки (1, 3, 6, 12 месяцев) через Telegram Stars или внешние платежные системы.
Привлечение: Реализована реферальная система "Пригласи друга — получи Premium".
2. Технологический стек
Язык программирования: Python 3.11+
Фреймворк для бота: Aiogram 3.x (мощный, асинхронный, с поддержкой FSM).
База данных: PostgreSQL (надежная, масштабируемая СУБД).
Взаимодействие с БД: SQLAlchemy + Alembic (для ORM и управления миграциями).
Кэширование/FSM: Redis (для хранения состояний FSM между перезапусками).
Веб-сервер: Uvicorn (высокопроизводительный ASGI-сервер).
Оркестрация и развертывание: Docker + Docker Compose.
Фоновые задачи: APScheduler (для периодического мониторинга лимитов).
Парсинг: BeautifulSoup4 (для извлечения данных с веб-страниц).
3. Архитектура приложения
Система состоит из следующих взаимосвязанных модулей:
Telegram Bot (Aiogram): "Лицо" приложения. Обрабатывает входящие обновления от Telegram (команды, сообщения, нажатия на инлайн-кнопки), управляет состояниями пользователя (FSM) для таких сценариев, как ввод API-ключа.
Gemini Service: Модуль для взаимодействия с API Google. Получает ID пользователя и данные запроса, извлекает и расшифровывает его API-ключ, формирует и отправляет запрос к Gemini, обрабатывает ответы и специфичные ошибки (невалидный ключ, лимиты и т.д.).
Context Manager: "Умный" обработчик контекста. Перед отправкой запроса в Gemini он анализирует историю чата. Если она превышает установленный порог токенов, модуль автоматически запускает процесс суммаризации: старейшая часть диалога отправляется в Gemini для получения краткой выжимки, которая затем заменяет собой исходные сообщения.
Subscription Manager: Управляет всем, что связано с платными услугами. Обрабатывает колбэки от платежных систем (Telegram Stars), проверяет статус подписки пользователя, активирует и деактивирует Premium-статус.
Error Handler: Централизованный модуль для перехвата и обработки ошибок от всех частей системы (API Gemini, Telegram, БД). Сообщает пользователю о проблеме в понятной форме и логирует полную информацию для администратора.
Admin Module: Содержит хендлеры для команд, доступных только пользователям с флагом is_admin.
Background Task Manager (APScheduler): Отвечает за запуск периодических задач, в первую очередь — отказоустойчивого парсера для мониторинга лимитов Gemini.
4. Итоговая модель данных (Схема PostgreSQL)
1. users - Пользователи бота
Поле	Тип	Описание
telegram_id	BIGINT, PK	Уникальный ID пользователя в Telegram.
username	VARCHAR, nullable	Имя пользователя (@username).
created_at	TIMESTAMP	Дата регистрации.
api_key_encrypted	VARCHAR, nullable	API-ключ пользователя в зашифрованном виде.
subscription_plan	VARCHAR	План подписки ('free', 'pro', 'banned').
subscription_expires_at	TIMESTAMP, nullable	Дата окончания Premium-подписки.
is_admin	BOOLEAN	Флаг администратора.
reward_claimed	BOOLEAN	Получил ли пользователь награду за рефералов.
2. chats - Диалоги пользователей
Поле	Тип	Описание
id	Integer, PK	Уникальный ID чата.
user_id	BIGINT, FK -> users	Владелец чата.
title	VARCHAR	Название чата.
model_name	VARCHAR	Модель, привязанная к чату (e.g., 'gemini-1.5-flash').
created_at	TIMESTAMP	Дата создания.
current_chat_id	Integer, FK -> chats, nullable	ID активного чата пользователя в таблице users.
3. messages - Сообщения в чатах
Поле	Тип	Описание
id	BIGINT, PK, Auto-inc	Уникальный ID сообщения.
chat_id	Integer, FK -> chats	К какому чату относится.
role	VARCHAR	Роль отправителя ("user" или "model").
content	TEXT	Текст сообщения.
timestamp	TIMESTAMP	Время отправки.
4. subscription_products - Доступные для покупки планы
Поле	Тип	Описание
id	SERIAL, PK	ID продукта.
name	VARCHAR	Название, видимое пользователю ("Premium на 1 месяц").
duration_days	INT	Срок подписки в днях.
price_stars	INT	Цена в Telegram Stars.
price_external	NUMERIC(10,2)	Цена для внешних провайдеров.
currency	VARCHAR(3)	Валюта (e.g., "USD").
is_active	BOOLEAN	Включен ли этот план для покупки.
5. referrals - Учет приглашенных пользователей
Поле	Тип	Описание
id	SERIAL, PK	ID записи.
referrer_id	BIGINT, FK -> users	Кто пригласил.
referred_id	BIGINT, FK -> users	Кого пригласили (уникальный).
created_at	TIMESTAMP	Когда был сделан переход.
6. settings - Настройки бота (управляются вручную)
Поле	Тип	Описание
key	VARCHAR, PK	Ключ настройки.
value	VARCHAR	Значение.
description	TEXT	Описание настройки.
Примеры ключей	referral_target_count, referral_reward_days	
7. gemini_limits - Данные о лимитах моделей (обновляются автоматически и вручную)
Поле	Тип	Описание
model_name	VARCHAR, PK	Название модели ('gemini-1.5-pro').
requests_per_minute	INT	Лимит запросов в минуту (RPM).
requests_per_day	INT	Лимит запросов в день (RPD).
tokens_per_minute	INT	Лимит токенов в минуту (TPM).
last_updated	TIMESTAMP	Когда значения были в последний раз обновлены.
5. Пользовательские сценарии (User Flows)
Первый запуск /start:
Бот приветствует пользователя и объясняет концепцию BYOK.
Предлагает инлайн-кнопки: [🔑 Добавить API ключ], [⭐️ Узнать о Premium], [🎁 Пригласи друга - получи Premium] и [❓ Где взять ключ?].
Управление API-ключом (/key):
Пользователь может ввести/изменить, удалить или проверить статус своего ключа.
При вводе бот переходит в режим ожидания (FSM). После получения ключа делается тестовый запрос к Gemini для валидации. Ключ сохраняется в БД в зашифрованном виде.
Управление чатами (/chats):
Отображается список всех чатов пользователя с указанием активного.
Инлайн-кнопки позволяют переключиться на любой чат, а также создать новый, переименовать или удалить текущий.
При попытке создать чат сверх лимита (1 для Free, 10 для Premium) бот предложит купить подписку.
Покупка и управление подпиской (/premium):
Для Free-пользователя отображается список доступных планов (из таблицы subscription_products) с ценами в Telegram Stars.
Для Premium-пользователя отображается статус его подписки и дата окончания.
После выбора плана бот генерирует счет на оплату.
Реферальная система (/ref или кнопка):
Пользователю показывается его прогресс (например, "Приглашено 2/5 друзей").
Выдается уникальная реферальная ссылка (https://t.me/YourBot?start=ref<user_id>).
Есть кнопка "Поделиться" для удобства.
При достижении цели (например, 5 приглашенных) бот автоматически начисляет Premium-статус на N дней.
Ведение диалога:
Пользователь просто отправляет текстовое сообщение.
Бот мгновенно отвечает [Gemini Flow] Печатает... и редактирует это сообщение по мере готовности ответа.
Ответ от Gemini форматируется (поддержка Markdown) и отправляется пользователю.
6. Администрирование и мониторинг
Доступ: Команды доступны только пользователям с флагом is_admin = true.
Админ-команды:
/admin — Показывает админ-панель с кнопками-командами.
/stats — Выводит статистику: общее кол-во пользователей, новых за сегодня, активных Premium, сообщений за 24 часа.
/broadcast [сообщение] — Асинхронная рассылка сообщения всем пользователям с задержками для избежания лимитов Telegram.
/userinfo [telegram_id] — Информация о пользователе (статус подписки, кол-во чатов).
/grantpremium [telegram_id] [дни] — Выдать Premium-статус пользователю.
/revokeaccess [telegram_id] — Забанить пользователя (установить subscription_plan = 'banned').
/setlimits [model] [rpm] [rpd] [tpm] — Ручное обновление всех лимитов для модели. Пример: /setlimits gemini-1.5-pro 15 500 1000000.
Автоматический мониторинг лимитов:
Процесс: Раз в 24 часа фоновый процесс (APScheduler) парсит официальную страницу Google с лимитами (https://ai.google.dev/gemini-api/docs/rate-limits?hl=ru).
Отказоустойчивость:
Весь процесс обернут в try...except.
В случае любой ошибки (недоступность сайта, изменение верстки) парсер прекращает работу.
Бот продолжает использовать последние успешно сохраненные значения из таблицы gemini_limits.
Администраторам отправляется уведомление об ошибке, призывающее к ручной проверке и обновлению лимитов через команду /setlimits.
7. План разработки (Roadmap)
Этап 0: Подготовка (
Настройка Git-репозитория, Docker Compose (PostgreSQL, Redis, App).
Настройка проекта Aiogram, SQLAlchemy и Alembic для миграций.
Этап 1: MVP - Ядро функциональности 
Реализация моделей users, chats, messages.
Реализация полного цикла BYOK: /start, ввод и шифрование ключа, простой диалог с Gemini (без суммаризации).
Создание первого чата по умолчанию.
Этап 2: Управление чатами
Реализация команды /chats с инлайн-клавиатурой.
Логика переключения, создания, переименования, удаления чатов.
Этап 3: Монетизация и реферальная система 
Реализация моделей subscription_products, referrals, settings.
Интеграция с Telegram Stars.
Мидлварь для проверки подписки и доступа к моделям Pro.
Реализация логики реферальной системы.
Этап 4: Стабильность и улучшения 
Внедрение умной суммаризации контекста.
Настройка детального логирования и Error Handler.
Создание админ-панели и всех админ-команд.
Реализация фонового процесса для мониторинга лимитов.
Внедрение rate-limiting на уровне мидлварей Aiogram для защиты от флуда.
Этап 5: Развертывание и запуск
Аренда VPS и настройка серверного окружения.
Развертывание проекта через Docker Compose.
Финальное тестирование и запуск для первых пользователей.
